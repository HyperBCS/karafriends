# karafriends: build and tooling stack review

_2026-10-27. Research only; nothing in the repo was changed. Scope: bundler, dev loop, package manager, transpile, lint/format, hooks, tests, packaging, native build, CI. The runtime layer (GraphQL, Apollo, Relay, Sentry, UI libs) is reviewed separately; this note only covers how it ties into the tooling._

**How the numbers were measured.** I walked `yarn.lock` and summed `.yarn/cache` zip sizes. "Frees N pkgs / X MB" means packages reachable **only** through that tool, so removing it really drops them. Git sizes come from attributing every blob in the pack to its path. Current versions are from the npm registry, queried today. I ran `tsc --noEmit` (clean, about 3 s) and `tslint --project` (1 violation). Nothing was installed or built.

---

## TL;DR

The build stack has more moving parts than the app needs. Most of the bloat comes from two choices. **Yarn PnP with a committed, all-platform cache** accounts for 458 MB in the tree, 95% of a 2.5 GB `.git`, and 2,902 changed files in the last upstream merge, against 97 for source. **Parcel**, which hasn't had a release since February, accounts for 179 exclusive packages / 177 MB on its own (337 / 184 MB with the Babel presets and dev runners around it), the hand-written dev proxy, and the `import.meta.url` bug. The **wdio** stack adds another 465 packages / 94 MB and 38 Dependabot PRs a year, and it only runs on upstream's own Mac.

Recommended target: **Yarn 4 with `nodeLinker: node-modules`, cache not committed → electron-vite 6 (Vite 8) → Prettier unchanged + oxlint instead of tslint → drop wdio (or Playwright if you want e2e) → `@electron/packager` (renamed) + 7zip as today → native build unchanged.** All of it together drops about 956 of 1,835 packages (285 MB of today's 458 MB cache) and adds about 50. devDependencies go from 78 to about 39.

### 1.2 Dev loop

- `run-dev` → `cross-env NODE_ENV=development yarn _run-dev` → `yarn build-dev`, which runs `concurrently` [resources + `cargo` native build] + `relay-compiler`, then a **full `parcel build` of all four targets**. After that, `concurrently` runs `parcel serve --target remocon --target renderer --port 3000` alongside `wait-on :3000 && node electron.js build/dev/main_/index.js`. The renderer and remocon get built twice per start, and main/preload changes need a full restart with no watch.
- [electron.js](../electron.js) spawns Electron with `NODE_OPTIONS=--require .pnp.cjs --experimental-loader .pnp.loader.mjs` so the main process can resolve through PnP.
- In dev the renderer window loads `http://localhost:3000/renderer/` ([main/index.ts:174](../src/main/index.ts)). Express on :8080 sends everything except `/graphql` through [remoconReverseProxy.ts](../src/main/middleware/remoconReverseProxy.ts), a hand-written `fetch` proxy. It buffers whole responses, doesn't forward WebSocket upgrades (so no HMR on phones), and has **no `.catch()`**. If the Parcel server is restarting, a phone request rejects, reaches `process.on("unhandledRejection")` ([main/index.ts:22](../src/main/index.ts)), and that handler calls `Sentry.captureException` and `process.exit(1)`. The path-prefix bug fixed today (`remocon.<hash>.js`) was in this file.

### 1.6 Relay compiler (coupling only)

`relay-compiler` 21.0.1 (Rust; 40 MB zip, 118 MB unplugged because it ships all platforms) is configured by the `relay` key in package.json. `build-relay-dev` and `build-relay-prod` both just run `relay-compiler`. Its output (`__generated__/`, git-ignored) is needed by both the bundle and `tsc`. `relay-compiler-language-typescript` 15 and `relay-config` 12 are leftovers from the pre-v13 JS compiler, which now has TS built in. **Babel exists only for Relay.** If the runtime review removes Relay, then `.babelrc`, `babel-plugin-relay`, `@babel/core`, `relay-compiler` (−40 MB), both `build-relay-*` scripts and every `__generated__/` go with it, and the Vite setup below gets simpler too (no `vite-plugin-relay`).

## 2. Concrete problems

1. **Committed all-platform cache.** 458 MB / 1,779 files in the tree, 2.4 GB of history, and roughly 340 MB/yr of further growth from upstream. Every Dependabot PR is mostly zip churn, and merges are dominated by cache files.
2. **Dirty tree after `yarn install` on Windows.** Linux packages declare `"libc": ["glibc"]` (checked: `lightningcss-linux-x64-gnu`). `.yarnrc.yml` doesn't list `libc`, Yarn defaults it to the host's, and Windows has none, so Yarn prunes those zips. (One-line fix: `libc: [glibc]`. It goes away anyway once the cache isn't committed.)
3. **PnP friction everywhere.** The `electron.js` wrapper exists to inject `.pnp.cjs`; wdio needs `pnpify`; editors need `yarn dlx @yarnpkg/sdks` (and `.yarn/sdks` is git-ignored); plain `node script.ts` can't resolve packages; 988 MB of `unplugged` holds binaries for platforms you don't run. Electron Forge and electron-builder both expect `node_modules`, so PnP also blocks those.
4. **Parcel's `import.meta.url` rewrite.** It inlines a project-relative `file:///.yarn/...` URL, which crashed youtubei.js 18 on Windows and is now worked around with a yarn patch. The URL stays project-relative under `node_modules` too, so **switching the linker alone doesn't fix this; replacing Parcel does.**
5. **Dev loop.** It builds twice per start, has no main/preload watch, and needs 4 helper tools (`concurrently`, `wait-on`, `cross-env`, `electron.js`). The hand-written :8080→:3000 proxy has already had a path bug and has a **crash bug**: a refused proxy fetch leads to `unhandledRejection`, then `process.exit(1)`.
6. **Parcel is idle** (no release since 2026-02-02) and is the biggest tooling tree (179 exclusive packages / 177 MB). It also needs several workarounds: the error-overlay alias stub, `minBundles`, a stale `canvas` alias, auto-installed polyfills sitting in runtime deps, and `dict/` copied five times.
7. **Babel is mostly dead weight.** Three presets and runtime are unused, and four webpack loaders are still listed. The only live use is `babel-plugin-relay`.
8. **Deprecated tools:** tslint (2020), `electron-packager` (renamed), `wdio-electron-service` (renamed), `relay-compiler-language-typescript` and `relay-config` (pre-v13).
9. **E2E costs a lot and gives the fork nothing.** 465 packages, 38 Dependabot bumps a year, Unix-only scripts (`unbuffer`), a broken `ephemeral-port-reserve` script, and a CI job that only runs on upstream's self-hosted Mac.
10. **Node type stripping doesn't fit the code.** Node needs `import type` for type-only imports, explicit `.ts` extensions, and no `enum`s. The codebase uses extensionless imports and two enums, and tsc isn't set to enforce the first rule (`verbatimModuleSyntax` is off), so loading TS modules outside the bundle meant compiling into `build/`.
11. **Node 25+ dropped corepack.** This hurts less than it seems: `yarnPath` means any `yarn` binary, or plain `node .yarn/releases/yarn-4.6.0.cjs`, works. CI already uses `npm install -g yarn`. With npm, nothing is needed at all.
12. **Hooks and CI gaps.** Clippy runs on every commit, including JS-only ones. tslint and Prettier never run in CI, so the pre-commit hook is the only gate. Daily Dependabot with a limit of 1000 and auto-merge is a lot for a two-person project, and the fork duplicates it on top of what it pulls from upstream.

**About `import.meta.url`:** Rolldown/Vite rewrites `import.meta.url` in Node CJS output to the bundle's real `file://` path, and electron-vite targets exactly that output. So the youtubei.js patch should no longer be needed. **Check this on Windows** by removing the patch after the switch.

**Remocon dev serving options** (phones must reach one host:port that also serves GraphQL):

- (a) **Vite owns the front door in dev.** Bind it with `server.host: true` and proxy `/graphql` (`ws: true`) to Express :8080; in dev the QR code points at Vite's port. Express keeps only the prod `express.static` branch, so the hand-written proxy goes away. This is the recommended option.
- (b) Keep :8080 as the front door with a dev-only `http-proxy-middleware` (handles streaming and WebSocket upgrades). That's one small dependency.
- (c) Vite middleware mode inside Express (`app.use(vite.middlewares)`). This gives one port and no proxy, but the main process then has to load `vite` at runtime in dev, which pulls the dev server into the app's own code.

### 3.3 Babel

Needed **only** while Relay is used. Under Vite, the choices are `vite-plugin-relay` (Babel 8, runs only on files containing `graphql`), `@rolldown/plugin-babel` with `babel-plugin-relay`, or `@swc/plugin-relay` (requires the SWC React plugin instead of the default Oxc). ## 7. The 2.5 GB `.git` (options only; no history rewriting)

The facts: 95% of the pack is `.yarn/cache` history, and upstream adds about 340 MB/yr of new zips. Even after step 2, every `git fetch upstream` keeps pulling those blobs as long as upstream uses zero-installs.

1. **Leave it.** It costs nothing and is safe. It keeps growing about 340 MB/yr through upstream fetches.
2. **Fresh partial clone (recommended for the long run):** `git clone --filter=blob:none git@github.com:HyperBCS/karafriends.git`, then add `upstream` and set `remote.upstream.promisor=true` and `remote.upstream.partialclonefilter=blob:none`. It has every commit and tree, so merges and `git log` work and hashes don't change. Blobs are downloaded only for what gets checked out (or lazily for `log -p`/`blame` of old revisions). Expected `.git`: roughly the current checkout's blobs plus commits/trees — hundreds of MB before step 2, tens of MB after. Keep the old clone until the new one is verified.
3. **Partial clone + sparse checkout** that excludes `/.yarn/cache/` and `/.pnp.*` (non-cone patterns). Cache blobs are then never downloaded at all, even when upstream adds them. This pairs with the low-divergence "keep the files tracked but unused" variant of step 2.
4. **Shallow clone** (`--depth` / `--shallow-since`, which the README already suggests). It's the smallest, but merging upstream needs the merge base (`git fetch --shallow-since=<last sync>` / `--deepen`), and missing history causes confusing merge failures. A poor fit for a fork that syncs.
5. **Shrink the existing clone in place:** `git config remote.origin.promisor true` + `partialclonefilter blob:none`, then `git repack -a -d --filter=blob:none` (supported by the installed Git 2.49). It doesn't rewrite history, but it deletes local copies of blobs on the assumption that the remote has them. **Only do this after every local branch is pushed**, or unpushed blobs are lost. Option 2 gets the same result more safely.
6. **What doesn't help:** `git gc --aggressive` (zips are already compressed), or untracking the cache on its own (old blobs stay in history, and upstream keeps adding new ones).
